# 量化管理人综合能力评估助手

基于 goodluckdata.com 私募净值数据，对量化私募管理人进行**收益进攻、收益质量、风格偏离**三维评分，输出管理人排名与 Markdown 分析报告。

## 1. 设计背景与目标

在量化私募管理人研究中，常见的需求是：

- 横向对比多家管理人的综合能力；
- 快速定位管理人在收益进攻、收益质量、风格暴露上的相对位置；
- 在尽调前形成一份结构化、可复现的评估材料。

本 Skill 的设计目标是：把净值数据转化为**可横向比较、逻辑透明、口径一致**的综合评分，同时内置合规护栏，避免输出中隐含收益承诺或买卖建议。

### 核心设计原则

- **横向可比**：所有指标先做全市场分位数排名，再映射到 0–100 分。
- **三维独立**：进攻、质量、风格三个维度分别衡量不同能力，避免单一指标主导结论。
- **产品覆盖奖励**：产品数量越多，说明信息披露越完整，综合分给予适度奖励。
- **只看历史、不预测未来**：所有计算均使用评估截止日之前的数据，不依赖未来函数。

## 2. 评分体系

### 2.1 三个维度

| 维度 | 含义 | 核心逻辑 |
|---|---|---|
| **收益进攻评分** | 管理人获取收益的能力 | 300/500/1000指增及选股产品的近1年年化收益越高，得分越高 |
| **收益质量评分** | 管理人创造 Alpha 的能力 | 指增产品的年化超额收益越高、对冲产品的夏普比率越高，得分越高 |
| **风格偏离评分** | 管理人与基准风格的偏离程度 | 与基准指数相关性越高越“紧”，得分越高；与小市值相关性越高越“偏”，扣分越多 |

### 2.2 产品覆盖奖励系数

同一管理人覆盖的产品数量越多，信息披露越完整，奖励系数越高：

| 产品数 | 奖励系数 |
|---|---|
| 5 个 | 1.10 |
| 4 个 | 1.06 |
| 3 个 | 1.03 |
| 2 个 | 1.00 |

> 参与统计的产品指 300指增、500指增、1000指增、选股、对冲五条策略线。
> 旗下产品不足 2 个的管理人不参与评分。

### 2.3 综合分公式

```text
综合分 = (收益进攻评分 + 收益质量评分 + 风格偏离评分) / 3 × 奖励系数
```

结果四舍五入到 0.1，再按综合分降序排名。

## 3. 计算逻辑

### 3.1 数据来源与窗口

- **数据源**：goodluckdata.com HTTP 接口
  - 产品净值/累计收益：`/manager/get_leaderboard_data/`
  - 宽基指数收盘价：`/api/index_dashboard_data/`（沪深300、中证500、中证1000、中证2000、万得小市值）
- **数据窗口**：固定 2 年（104 周），用于数据对齐与日期统一
- **评估区间**：数据窗口的最后 1 年（52 周），用于最终评分
- **日期对齐**：若用户指定 `date`，以该日之前的最近周五为终点；否则使用 API 最新可用周五

### 3.2 从净值到指标

1. **周收益率**：

   ```text
   r_t = nav_t / nav_{t-1} - 1
   ```

2. **年化收益**（复利 52 周）：

   ```text
   annual_return = ∏(1 + r_t)^(52 / n) - 1
   ```

3. **年化波动率**：

   ```text
   volatility = std(r) × sqrt(52)
   ```

4. **夏普比率**（假设无风险利率为 0）：

   ```text
   sharpe = annual_return / volatility
   ```

5. **相关性**：
   - 产品周收益序列与对应基准指数（沪深300/中证500/中证1000）的皮尔逊相关系数
   - 产品周收益序列与万得小市值指数的皮尔逊相关系数

### 3.3 分位数排名

每个维度下，将所有纳入产品的指标做全局分位数排名：

- 第一名 = 100 分
- 最后一名 = 0 分
- 中间按分位数线性插值

管理人在某个维度的得分 = 其旗下各产品在该维度得分的**均值**。

### 3.4 风格偏离评分合成

```text
风格偏离分 = 0.7 × 基准相关性分 + 0.3 × (100 - 小市值相关性分)
```

- 与基准相关性越高 → 跟踪越紧 → 得分越高
- 与小市值相关性越高 → 小市值暴露越大 → 扣分越多

## 5. 快速开始

### 5.1 依赖

- Python 3.10+
- requests
- numpy
- reportlab（生成 PDF 测试报告及 README PDF 时使用）
- mistune（解析 Markdown 时使用）

安装：

```bash
pip install requests numpy reportlab mistune
```

### 5.2 运行示例

```bash
# 1. 全市场最新评估
python scripts/run_alpha.py --report --out report.md

# 2. 指定多家管理人最新评估
python scripts/run_alpha.py --managers "明汯,鸣石,衍复,平方和,世纪前沿" --report --out report.md

# 3. 指定历史截面
python scripts/run_alpha.py --managers "玉数,衍合,子午" --date 2025-12-31 --report --out report.md
```

不传 `--managers` 时，默认返回全市场管理人打分。

## 6. 输入与输出

### 6.1 输入变量

| 变量 | 类型 | 是否脱敏 | 说明 |
|---|---|---|---|
| `managers` | 文本 | 否 | 管理人名称，多个用逗号分隔；不传则评估全市场 |
| `date` | 日期 | 否 | 评估截止日 `YYYY-MM-DD`；不传则使用 API 最新可用日期 |
| `data` | 净值序列 | 是 | 由脚本从 goodluckdata.com 接口拉取，不外传原始净值明细 |

### 6.2 输出内容

默认输出 Markdown 报告，包含：

1. **评估要素表**：数据区间、数据窗口、数据来源、参与管理人、生成时间
2. **未匹配管理人提示**（仅当指定了 `managers` 且部分名称未找到时）
3. **评分规则说明**：进攻/质量/风格/奖励系数/综合分
4. **管理人排名表**：排名、管理人、产品数、三维得分、奖励系数、综合分
5. **重点管理人归因解读**：引用年化收益、年化超额/夏普、相关系数等具体数值，解释三维得分优劣
6. **重点管理人明细**：产品原始指标
7. **风险提示**（末尾必含）

若不加 `--report`，则输出 JSON 格式，便于下游自动化处理。

## 7. 合规与风险提示

- 本评估只衡量管理人在**特定区间内的相对表现**，不预测未来收益。
- 禁止出现“保本”“稳赚”“无风险”等承诺性表述。
- 禁止预测具体涨跌幅或给出确定性买卖建议。
- 敏感数据脱敏：只输出管理人名称与计算指标，不输出 `fund_code / fund_name / 原始净值明细`。
- 数据引用需注明来源与生成时间，不得伪造数据来源、测试记录或提效结果。

> 历史业绩不代表未来表现，私募产品存在净值波动与本金损失风险，请以基金管理人正式披露信息为准。
